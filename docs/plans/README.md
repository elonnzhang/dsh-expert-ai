# docs/plans：已定的设计

这里收录 dsh-expert-ai 已经定下的设计：为什么这样做、已定的行为、不做什么、已知限制。拿不准一个现象是 bug 还是设计如此时，先查这里；这里没写的，在 Issue 里问。格式与 DeepSeek-Bot 的 `docs/plans/` 一致，方便两个项目对照。

## 什么时候写

- **大功能**：在同一个 Pull Request 里附一份 `docs/plans/<日期>-<主题>.md`，和代码一起审、一起合。
- **改动已定的设计**：先在 Issue 里和维护者确认，合并时同步改对应文档的「变更」。
- **修 bug**：不用写。

## 格式

```markdown
# 标题

- 日期：设计定下的日期
- 相关：Issue / PR 编号

## 为什么
## 已定的行为
## 不做什么
## 已知限制
## 变更
```
